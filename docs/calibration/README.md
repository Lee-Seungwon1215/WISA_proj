# Timing backend calibration

`timing_backend_v2.json` is generated by:

```bash
python scripts/calibrate_timing_backend.py
```

It runs deterministic synthetic A/A trials and an injected standardized-effect
curve through the pinned official-dudect C backend. It also feeds one analysis
trace to the upstream uncropped test and CT-KAT's Python Welch implementation,
then records their numerical delta.

This artifact validates the **statistical adapter**, not a cryptographic timing
experiment. It cannot make a target run `timing_validity=valid`. Physical A/A,
positive-control, pool/common-buffer symmetry, repeated processes, and native
host checks are implemented by timing-harness-v2, but must still be executed
and accepted for each concrete target/host. The committed corpus refresh is
separate work.
