# V10 single-host 결과 회수·검증·논문 주입 런북

기준 commit: `1aeadb97e0409227aa203ba825a6bfc1d90445bc`
최종 범위: 물리 Linux x86_64 host 1대, component 4개, target execution 26개,
primary timing axis 28개, protocol row 8,220,000개

## 0. 제일 중요한 경계

측정과 named analysis는 **clean frozen checkout**에서 끝낸다. 현재 MDPI 논문
브랜치에는 원고/검사기 변경이 있으므로 여기서 analyzer를 억지로 실행하면 안 된다.
논문 브랜치는 완성된 `paper_native_analysis.json`을 읽기만 한다.

다음은 모두 탈락이다.

- final marker 없이 일부 component만 있는 상태
- pilot/engineering/legacy 결과 혼합
- 다른 commit, host identity, CPU/compiler, control qualification 혼합
- 실패 후 같은 final 디렉터리를 이어서 resume한 결과
- 28축보다 적거나 많은 analysis
- analyzer의 `--check-output`이 byte drift를 보고한 결과
- 원자료를 복사하면서 hash가 달라진 결과

## 2. 원격 frozen checkout에서 읽기 전용 확인

아래에서 `/path/to/ctkat`만 실제 경로로 바꾼다.

```bash
cd /path/to/ctkat
git rev-parse HEAD
git status --porcelain --untracked-files=no
test -f measurement_runs/v10-final-complete.txt
sed -n '1,120p' measurement_runs/v10-final-complete.txt
find measurement_runs/host-a -maxdepth 2 -type f \
  \( -name campaign_report.json -o -name baseline_report.json \) -print | sort
```

판정:

- HEAD는 위 40자리 commit과 정확히 같아야 한다.
- tracked worktree 출력은 없어야 한다.
- marker는 단순 존재뿐 아니라 orchestrator가 성공 완료를 기록했는지 읽어 본다.
- 네 `campaign_report.json`과 세 baseline report가 있어야 한다.

## 3. bundle 생성

orchestrator가 이미 같은 bundle을 만들었다면 먼저 보존하고 검증한다. 없다면 clean
frozen checkout에서 다음을 실행한다.

```bash
uv run --frozen python scripts/build_single_host_measurement_bundle.py \
  --host-root measurement_runs/host-a \
  --output measurement_runs/v10-single-host-bundle.yaml \
  --host-id host-a \
  --analysis-output measurement_runs/analysis/v10-named
```

이 builder는 네 component, 세 baseline, 한 host/commit/CPU/machine identity, final
gate, 두 clean control rehearsal qualification, assembly evidence, unique run ID를 함께
검사한다. 성공하면서 `host-a/SHA256SUMS`도 만든다. 에러가 나면 bundle YAML을 손으로
조작하지 말고 해당 원자료를 원인별로 판정한다.

## 4. named analysis 최초 생성 또는 재검증

output directory가 아직 없다면 최초 생성:

```bash
uv run --frozen python scripts/analyze_paper_native_results.py \
  --bundle measurement_runs/v10-single-host-bundle.yaml \
  --verification-commit 1aeadb97e0409227aa203ba825a6bfc1d90445bc \
  --output-root measurement_runs/analysis/v10-named \
  --output-mode named
```

이미 analyzer output이 존재한다면 덮어쓰지 말고 byte 재검증:

```bash
uv run --frozen python scripts/analyze_paper_native_results.py \
  --bundle measurement_runs/v10-single-host-bundle.yaml \
  --verification-commit 1aeadb97e0409227aa203ba825a6bfc1d90445bc \
  --output-root measurement_runs/analysis/v10-named \
  --output-mode named \
  --check-output
```

`--check-output` 성공이 필수다. 새 output을 얻겠다고 기존 named directory 내용을
지우는 행동은 하기 전에 원본 archive를 먼저 보존한다.

## 5. 최상위 hash manifest

orchestrator가 만든 manifest가 있으면 다음으로 검증한다.

```bash
uv run --frozen python scripts/hash_artifacts.py \
  measurement_runs \
  --check measurement_runs/v10-final-top-level-SHA256SUMS
```

manifest가 없는 새 회수 절차라면 모든 bundle/analysis/marker가 확정된 뒤 한 번만
생성하고 곧바로 check한다.

```bash
uv run --frozen python scripts/hash_artifacts.py \
  measurement_runs \
  --write measurement_runs/v10-final-top-level-SHA256SUMS
uv run --frozen python scripts/hash_artifacts.py \
  measurement_runs \
  --check measurement_runs/v10-final-top-level-SHA256SUMS
```

## 6. 복사

원격 전체 `measurement_runs/`는 원본 artifact로 보존하고, 논문 주입에는 최소한
아래 두 파일을 함께 가져온다.

- `measurement_runs/analysis/v10-named/paper_native_analysis.json`
- `measurement_runs/v10-final-top-level-SHA256SUMS`

가능하면 전체 디렉터리를 hash 보존형 archive로 복사한다. 복사 전후
`paper_native_analysis.json`의 SHA-256을 따로 기록하고 비교한다. 비밀번호나 접속
정보는 문서/쉘 history/논문 artifact에 넣지 않는다.

## 7. MDPI 논문 브랜치에 결과 주입

논문 checkout에서:

```bash
bash scripts/build_mdpi_paper.sh \
  --analysis /copied/v10-named/paper_native_analysis.json \
  --refresh
```

이 명령은 다음을 모두 수행한다.

1. commit과 exact 28-axis/8+10+6+4 구성을 검증한다.
2. 네 component table과 abstract/result summary를 생성한다.
3. generated byte, citation, label, stale value, MDPI upstream hash를 검사한다.
4. 공식 MDPI class로 PDF를 빌드한다.
5. undefined reference와 2 pt 초과 overfull box를 검사한다.

그 뒤 재현성 확인:

```bash
bash scripts/build_mdpi_paper.sh \
  --analysis /copied/v10-named/paper_native_analysis.json
```

두 번째 명령은 생성 파일을 수정하지 않고 같은 입력이 같은 byte를 내는지 검사한다.

## 8. 자동화 뒤에도 사람이 읽어야 하는 것

- 네 evidence-state count 합이 28인지.
- 각 행의 target/harness/axis가 preregistration과 맞는지.
- `FAIL`, `WARNING`, invalid/confounded, `PASS`가 각각 허용된 claim으로만 번역됐는지.
- chosen-ciphertext, mixed valid-tuple, operand canary, Falcon output-length 경계가
  본문에서 유지되는지.
- single-host 결과를 다른 CPU, ARM/M4, 일반 구현 전체로 확장한 문장이 없는지.
- 예상 밖 결과를 숨기거나 threshold를 사후 변경한 흔적이 없는지.

## 9. 결과 이후 실제 남는 일

결과 ingestion과 PDF 검증 뒤에는 저널 선택, 저자/소속/CRediT, 연구비/이해상충,
artifact DOI, 최종 영어 교정, 제출 ZIP clean-room build만 남는다. 두 번째 host,
2인 review, M4 backend는 추가 연구 가치가 있지만 현재 V10 논문을 완성하기 위한
숨은 필수조건으로 취급하지 않는다.
