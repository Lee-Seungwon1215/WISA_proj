# CT-KAT MDPI working manuscript

This directory is the result-integrated English manuscript, migrated from the
old WISA/LNCS draft to the official 2026 MDPI article class. The complete V10
single-host named analysis is rendered into 28 primary axes and preregistered
secondary summaries. Pilot, failed, partial, and legacy timing values remain
deliberately absent.

## One-command build

From the repository root:

```bash
bash scripts/build_mdpi_paper.sh \
  --analysis /path/to/v10-named/paper_native_analysis.json
```

The PDF is written to
`paper/mdpi_working/build/CT-KAT_MDPI_draft.pdf`. Build outputs are ignored by
Git.

## Recreate the final native result

Use only the complete named analyzer output produced and rechecked in the
clean measurement checkout at commit
`1aeadb97e0409227aa203ba825a6bfc1d90445bc`:

```bash
bash scripts/build_mdpi_paper.sh \
  --analysis /path/to/v10-named/paper_native_analysis.json \
  --refresh
```

The renderer refuses the input unless it is a named single-host analysis with
exactly 28 unique preregistered axes, the expected 8/10/6/4 component split,
one host, complete evidence-state counts, and both commit fields bound to the
frozen measurement commit. The generated state stores the input byte hash but
not a machine-specific absolute path.

After generation, omit `--refresh` to prove that the checked-in inputs are
byte-for-byte reproducible:

```bash
bash scripts/build_mdpi_paper.sh \
  --analysis /path/to/v10-named/paper_native_analysis.json
```

Never edit files under `generated/` by hand. The final analysis also remains a
single-host result; it does not create cross-host replication, an independent
human review, or an architecture-general claim.

## Source layout

- `main.tex`: manuscript and all non-generated prose.
- `references.bib`: bibliography migrated and checked for missing keys.
- `generated/static_results.tex`: committed-corpus, ablation, and V10 scope.
- `generated/native_summary.tex`: pending/complete state and abstract/result macros.
- `generated/native_results.tex`: explicit pending block or final 28-axis tables.
- `generated/render_state.json`: deterministic generation provenance.
- `Definitions/`: hash-pinned official MDPI class assets.
- `upstream/template.tex`: untouched upstream example for comparison.
- `UPSTREAM.md`: acquisition provenance and pinned hashes.

## Gates and remaining human inputs

`scripts/check_mdpi_paper.py` checks the MDPI assets, required sections and
back matter, citations, labels, stale WISA/native claims, generated bytes, and
material overfull boxes. Without `--allow-pending`, a pending native table is a
hard failure.

The native result and PDF gates are complete. The following cannot be inferred
from code or measurements and must be filled before submission: final MDPI
journal/class option, author names and
affiliations, corresponding author, CRediT roles, funding, conflicts of
interest, acknowledgments, repository/archive DOI, and the journal's current
AI-disclosure wording.

The Cortex-M4 backend is future work. It is not mixed into this x86_64 V10
paper result and does not require rerunning the frozen campaign.

Use `scripts/package_mdpi_submission.sh --draft` for an explicitly
non-submittable anonymized source package. The default strict packaging mode
rejects unresolved author, funding, conflict, and artifact-identifier fields.
